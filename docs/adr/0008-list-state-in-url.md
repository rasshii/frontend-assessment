# 0008. 一覧の条件を URL に置く

## 状態

採用

## 文脈

一覧の条件は、ページ、ソートの列と向き、検索語の 4 つです。リロード、戻る・進む、URL の共有で、同じ一覧を出したいです。URL のクエリは React Router の `useSearchParams` で読み書きします ([ADR 0001](0001-vite-react-spa.md))。

URL は利用者が手で書き換えられるので、解釈できない値や、存在しないページが来ることがあります。

## 決定

- 一覧の条件の正本は URL のクエリ (`page`・`sort`・`order`・`search`) にする。条件は React の state に写さず、URL から解釈して使う。操作は URL を書き換え、URL が変わると取得のキーが変わって取り直す ([ADR 0007](0007-api-side-query-and-tanstack-query.md))。
- 既定値 (1 ページ目、名前の昇順、検索語なし) は URL に書かない。初期状態の URL はクエリの無い形になる。
- 解釈できない値は、項目ごとに既定値にし、ほかの項目は残す。ページは 1 以上の整数の表記で、安全な整数に収まる値だけを受け、検索語は前後の空白 (全角を含む) を除く。解釈は zod のスキーマで行い、項目ごとに `.catch(既定値)` を付ける。
- URL を書き換えるのは、URL を読み書きする hook ([ADR 0005](0005-feature-directories-and-dependency-rules.md)) が返す 4 つの操作だけにする。1 回の操作は、URL の 1 回の書き換えにまとめる。
  - ページを変える: 履歴に積む。
  - ページを置き換える: 履歴を置き換える。最終ページへの移動に使う。
  - ソートを切り替える: ページを 1 に戻し、履歴に積む。
  - 検索を確定する: 前後の空白を除き、ページを 1 に戻し、履歴に積む。
- 条件が変わらない操作 (いまのページの番号を押した、同じ検索語で確定した) では URL を書き換えない。いまの URL は既定値を書いていたり並びが違ったりしうるので、いまの条件を書き出した形どうしで比べる。
- 検索を確定したとき、確定した条件がいまと同じ (同じ検索語で 1 ページ目) なら、URL は変えずに同じ条件を取り直す。押しても何も起きないように見えるのを避けるため。
- 検索語は確定したときだけ URL に書く (入力中の文字は検索欄の中だけで持つ。[ADR 0006](0006-react-compiler.md))。戻る・進むで URL の検索語が変わったときは、検索欄の値をそれに合わせる。
- 操作部品の状態 (ソート中の列と向き、選択中のページ番号) は URL から決め、行と件数表示は取得結果から決める。ページャは両方を受ける (選択中の番号は URL、総ページ数は結果)。
- いまの条件の結果が範囲外 (要求したページが最終ページより後ろ) なら、URL を最終ページに置き換える。置き換えるまでは一覧を出さず、ローダーだけを出す。前の条件の結果を引き継いでいるあいだは、その結果が範囲外でも置き換えない。

## 根拠

- 条件が URL にあるので、リロード、戻る・進む、URL の共有で同じ一覧を再現できます。
- 条件を URL だけに持つので、state と URL の 2 か所をそろえる処理が要りません。
- 既定値を書かないので、書き出す URL は条件ごとに 1 つの形になり、初期状態の URL は素のままです。
- 解釈できない値で画面を止めず、どの値からでも一覧を出せるように、既定値に落とします。項目ごとに落とすので、1 つの項目が解釈できなくても、ほかの項目 (たとえばページ) は残ります。zod 4.6.7 の `.catch(値)` は、検証に失敗したとき (値が `null` のときを含む) その値を返します。`URLSearchParams` の `get` は項目が無いと `null` を返すので、項目が無い場合と解釈できない場合を、同じ書き方で既定値にできます。
- 条件を変える操作をすべて履歴に積むので、戻る・進むで前の条件の一覧に戻れます。最終ページへの移動は履歴を置き換えるので、戻ったときに範囲外の URL には戻りません。
- 1 回の操作を 1 回の書き換えにまとめるのは、`setSearchParams` が、同じタイミングでの複数回の呼び出しを積み上げないためです (React Router の `useSearchParams`)。
- 前の一覧を残しているあいだ ([ADR 0007](0007-api-side-query-and-tanstack-query.md))、URL の条件と、出している結果の条件は一時的に違います。操作部品はいま選ばれている条件を示し、行と件数表示は出している結果と食い違わないように、出どころを分けます。このあいだは URL のページが結果の総ページ数を超えることがあるので、ページャは総ページ数までの番号を出し、選択中の番号はなしにします。
- 範囲外は、URL を直接書き換えたときに起きます。API は範囲外のページに、200・空の行・元の総件数を返します (実測)。範囲外の結果は表示に使えないので、最終ページに移るまでローダーを出します。引き継いでいる前の条件の結果が範囲外でも、いまの URL のページが範囲外とは限らないので、置き換えの判断には使いません。

## 採らなかった案

- **React の state に持ち、URL と同期する**: 状態が 2 か所になり、そろえる処理が要ります。
- **状態管理のライブラリを入れる**: 画面は 1 つで、画面をまたいで共有する状態がありません。
